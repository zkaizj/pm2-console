# 本机日常运维驾驶舱设计

## 目标

将 PM2 中控台重组为一台 Windows 电脑上的日常运维驾驶舱。用户应能在 30 秒内发现异常服务、理解当前原因、查看相关日志，并以可确认、可验证的方式恢复服务。

## 已确认的使用环境

- 仅供单个操作者在本机使用，服务继续默认绑定 `127.0.0.1`。
- 日常稳定运维是主流程；项目发布已有其他成熟服务承担。
- 常用操作包括扫描本机进程、纳入 PM2、持续监控常用服务，以及在 PM2 或电脑重启后恢复服务和中控台元数据。
- 现有项目发布、插件和告警能力保留，但不再占据日常运维主界面。

## 成功标准

1. 打开页面时，用户无需浏览完整服务表即可看到异常、停止、未监测和在线服务数量。
2. 每个异常服务都能直接进入日志或恢复操作，且恢复后的实际状态可见。
3. 所有破坏性操作均在执行前说明影响并要求确认；删除需要输入服务名确认。
4. 从扫描进程到 PM2 纳管不应意外终止原进程；替换原进程仅在新实例已验证后进行。
5. 每次服务清单或元数据变化后，PM2 快照与中控台状态均已保存，重启后能恢复。

## 信息架构

### 日常导航

侧栏只显示三个高频入口：

1. **运维总览**：默认页，聚合待处理异常、关注服务和恢复保护状态。
2. **服务**：完整服务清单、分类筛选、手动纳管和扫描纳管入口。
3. **日志**：跨服务检索；从异常项或服务详情进入时自动带入服务和错误关键词。

“更多工具”收纳项目发布、插件管理和告警设置。项目数据、部署历史和现有 API 均继续可用，但项目不再出现在默认导航。进程扫描作为“服务”页中的纳管入口，避免用户先判断“进程”和“服务”应去哪个页面。

### 运维总览

页面从上到下依次展示：

1. PM2 连接状态、最后刷新时间、在线/异常/停止/未监测数量。
2. **待处理**：异常进程、意外停止的关注服务、健康检查失败服务。每项显示状态、最近重启次数、健康失败原因或最近错误摘要，并提供“查看日志”“重启”“忽略本次”。
3. **关注服务**：用户手动置顶的服务，展示状态、CPU、内存、健康状态和最近异常，不把所有服务都堆到首页。
4. **恢复保护**：上次成功保存 PM2 快照和元数据的时间、当前保存是否失败，以及“立即保存快照”动作。

未配置健康检查的服务显示“未监测”，而不是绿色健康状态。健康失败要显示最近检测时间、HTTP 状态或连接错误。

### 服务与详情

服务列表展示名称与备注、分类、状态、健康、资源、重启次数和最近动作。分类仅用于筛选，不承载日常配置流程。

点击服务打开统一详情面板，分为四个区段：

1. **状态与操作**：当前状态、运行时长、资源和安全的启动、停止、重启、删除操作。
2. **日志**：最近错误与输出；一键跳转到已带条件的日志搜索。
3. **监控**：当前资源趋势与关注开关。
4. **配置**：备注、页面地址、健康检查地址与关键字；可立即执行健康检查并显示结果。

执行操作后的共同状态机是“确认 → 处理中（按钮禁用）→ 后端结果 → 自动刷新并展示最终状态”。停止、重启和删除均要求确认；删除使用输入服务名的二次确认。失败保留服务详情和失败原因，不以短暂 toast 代替诊断结果。

### 纳管流程

服务页提供“手动纳管”和“扫描本机进程”两个明确入口。扫描结果显示名称、可执行路径、命令行、PID 和 PM2 托管状态；已托管的进程不可重复纳管。

选择候选进程后，进入预填确认步骤：服务名、工作目录、分类、备注、页面地址、健康检查、是否关注。默认操作为“仅由 PM2 新建实例”，不触碰原进程。

“纳管并停止原进程”采用安全交接：

1. 用确认后的参数由 PM2 启动新实例。
2. 等待 PM2 在线；若配置健康检查，则等待健康通过。
3. 向用户展示新实例验证结果，再请求确认关闭原 PID。
4. 任一步失败时保留原进程，不执行关闭，并显示下一步诊断入口。

纳管完成后，服务被高亮定位到清单，提示“已纳管、已保存”。

## 持久化与恢复

中控台为每次会改变受管集合或元数据的成功操作创建一个保存动作：手动纳管、扫描纳管、启动、停止、删除、分类修改、服务配置修改、关注状态修改和项目/插件配置修改。

保存动作包含两部分：

1. 将分类、备注、页面地址、健康设置、关注状态和最近快照状态写入本地状态文件，并使用原子写入与最近一份备份保护配置。
2. 调用 PM2 保存进程快照；只有 PM2 确认成功后才把“最近快照时间”标记为成功。

保存失败必须在当前操作结果和“恢复保护”模块中长期可见，并提供重试。PM2 守护进程重启后，已保存的进程快照用于恢复服务；中控台重新连接 PM2 后从状态文件恢复分类、元数据和关注服务。浏览器的本地存储不承担服务恢复职责。

## 告警、插件与项目发布

- 告警设置保留在更多工具中，默认关闭；配置页不回显完整 Webhook，提供“发送测试”动作和明确结果。
- 插件管理保留在更多工具中，显示启用状态及禁用会影响的界面/API；插件不应破坏核心运维页加载。
- 项目发布保留在更多工具中，不纳入首页待处理和常规服务操作。此轮不扩展部署流水线功能。

## 错误处理与展示原则

- 全局连接失败展示持久横幅并给出重试；模块失败只在本模块显示错误，不清空已加载的其他模块。
- 任何异步操作展示进行中状态，禁止重复提交。
- 失败文案优先说明“发生什么、影响什么、下一步做什么”，例如端口占用时建议查看原进程或采用安全交接。
- 桌面窗口优先保证总览和服务页可读；窄窗口将服务表改为可展开条目，关键状态和操作不依赖横向滚动。

## 不在本轮范围内

- 局域网、VPN 或公网远程访问、多用户角色和审计协作。
- 替代已有成熟服务的项目发布系统。
- 长期历史指标、移动端专用界面和新的外部 SaaS 集成。

## 验收场景

1. 一个服务异常时，总览在刷新后将其放入待处理，并能从该项查看日志、重启并看到最终在线状态。
2. 服务未配置健康检查时显示未监测；配置不可访问地址并立即检测时显示失败原因和检查时间。
3. 扫描到非 PM2 进程后，普通纳管不停止原进程；安全交接在新实例未验证时不允许关闭原 PID。
4. 启停、删除和元数据修改后，保存状态显示成功；模拟 PM2 恢复后服务清单和元数据仍存在。
5. 保存 PM2 快照失败时，当前操作和恢复保护均显示失败并可重试。
6. 项目、插件和告警仍能从更多工具进入，且不会影响总览、服务和日志主流程。
