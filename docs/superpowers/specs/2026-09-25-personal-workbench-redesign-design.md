# 个人工作台与软件接入设计

## 产品定位

把 PM2 中控台建设成单人本机使用的个人工作台。打开页面后，用户先确认 PM2 与关注服务是否正常；需要工作时，可从统一搜索快速打开已登记的软件、项目目录、文件、链接和服务。工作空间负责整理，不能成为找到内容的必经步骤。

本机服务稳定运维是第一优先级，个人工作内容快速查找是第二优先级。项目发布已有成熟服务承担，不继续扩展为另一套部署平台。

## 用户与边界

- 用户在自己的 Windows 电脑上使用网页版；服务只绑定本机。
- 数据保存在本机。工作台保存路径、网址、说明、标签和最近使用时间，不复制工程或文件。
- 账号密码仍由用户保存在自己的文件中；工作台只保存文件路径和说明，不读取或索引文件内容。
- 不自动扫描整台磁盘建立私人资料索引。全局搜索覆盖 PM2 服务、用户登记的软件/插件和工作台条目。
- 不从网页任意下载并执行 GitHub 项目。引入第三方项目之前，先核对活跃度、许可证、Windows 支持、依赖和所需权限。

## 日常使用流程

1. **检查运行情况**：首页显示 PM2 连接状态、关注服务运行情况、已配置的健康检查结果、异常原因和最近刷新时间。
2. **处理异常**：从异常服务直接打开日志、重启或进入详情；操作后显示最终状态、结果和下一步。
3. **快速找到工作内容**：顶部统一搜索服务、已登记的软件、工作台条目；也可从收藏和最近使用直接打开。
4. **登记常用内容**：用短表单保存一个软件、项目、目录、文件、链接或服务入口；空间、标签、说明可后补。
5. **纳管需要长期运行的进程**：从完整进程清单选中程序，明确选择关注、交给 PM2 管理或结束；交给 PM2 时说明会启动新实例，不会附着到现有 PID。

## 首页与导航

页面顶部提供统一搜索/快速打开入口。结果按“关注服务、全部服务、软件和插件、工作台条目”分组，展示名称、状态/类型、路径或网址摘要和可用动作；支持键盘打开、上下选择和回车执行。搜索仅查本机已登记数据，不遍历磁盘。

首页默认显示：

1. **连接与概览**：PM2 是否连接、在线/异常/停止数量、最后刷新时间。
2. **待处理**：异常服务、非预期停止、健康检查失败；操作入口直达日志、重启和详情。
3. **关注服务**：用户选择的常用服务，展示进程状态、健康状态和是否由 PM2 管理。
4. **最近工作内容**：最近打开和收藏的常用软件、工程、目录、文件、链接；视觉优先级低于运维状态，但一键可达。
5. **恢复状态**：最近一次 PM2 快照结果，以及 Windows 登录恢复是否已配置/验证；区分 `pm2 save` 与 `pm2 resurrect`。

主导航为“总览、服务、工作台、日志”；项目发布、告警和插件设置放入次级入口。

## 状态模型

界面分开呈现以下状态，避免“关注了”被误解为“已经监控并能恢复”：

- **关注**：显示在首页，便于查看；它本身不改变进程生命周期。
- **PM2 管理**：PM2 负责启动、停止、重启和崩溃后拉起；进程清单由 PM2 管理，快照纳入恢复流程。
- **健康检查**：通过用户配置的 HTTP(S) 地址判断服务是否可用；未配置时显示“未监测”，不能显示健康。
- **恢复验证**：PM2 快照已保存，以及 Windows 登录后是否配置并验证 `pm2 resurrect`。快照已保存不代表登录自启已验证。

每个服务可同时被关注、PM2 管理并配置健康检查；这些能力不可互相冒充。

## 本机进程管理

服务页内提供“本机进程”清单，展示 Windows 查询返回的全部进程，包括系统进程、PM2 已托管进程，以及路径/命令行不可读取的进程。展示名称、PID、路径、命令行、会话/类别和 PM2 归属；支持名称、路径和 PID 过滤，并清楚显示扫描时间、数量和错误。

- PM2 已托管进程仍在清单显示，启停动作调用 PM2，不重复导入或误用系统结束操作。
- 普通进程允许查看、结束或登记为关注项；结束前确认对象和影响。
- 系统/受保护进程显示保护原因，不提供结束和纳管快捷操作。
- “交给 PM2 管理”会使用用户确认的启动配置新建 PM2 实例。界面不得称其为对现存 PID 的直接接管。
- 仅当用户单独确认且替代服务在线、已配置健康检查时健康检查通过，才允许关闭原进程。验证失败时原进程继续运行。

## 通用软件接入

### 接入方式

软件目录是用户选择要整合的软件的入口。每个软件可配置一种或多种清晰标记的能力：

1. **快速打开**：登记本机程序路径或网页地址；仅负责打开，不声称由 PM2 运行或监控。
2. **PM2 服务**：登记启动命令、工作目录和必要环境变量，让适合后台运行的软件由 PM2 管理，并可配置健康检查。
3. **深度集成**：需要专属界面、数据展示或操作时，为选定软件提供集成适配器/插件。插件说明提供的动作、读取的数据和所需权限；加载失败不影响核心功能。

所有接入都能通过统一搜索找到，并可加入收藏或工作空间。接入卡片显示已配置能力、运行状态和下一步操作。桌面交互软件默认是“快速打开”；只有适合后台运行的程序才显示 PM2 服务能力。

### 引入现成项目的决策流程

用户提出想整合的软件或 GitHub 项目时：

1. 检查官方仓库的近期提交/发布、关注度、许可证、Windows 支持、安装依赖和权限要求。
2. 判断它是可独立打开的软件、可由 PM2 管理的后台服务，还是需要专属数据/API 的深度集成。
3. 优先以外部程序或服务方式接入，避免把完整应用复制进中控台造成重复运行、升级冲突和维护负担。
4. 只有确认不存在合适的成熟项目，或需要的体验无法通过现成项目实现时，才开发最小适配器；不能为了抽象而预建通用插件市场。
5. 每个候选集成在加入前提供简明说明：它解决什么问题、哪些能力可用、需要什么依赖/权限、许可证和维护状态。

插件现有机制可以作为某些深度集成的实现选项，但不是唯一的软件接入口。是否采用现成应用、插件或最小适配器，由逐个软件的兼容性评估决定。

## 工作台条目

条目类型包括软件、工程、目录、文件、在线链接、账号文件、PM2 服务和其他。每条记录名称、类型、目标、说明、标签、收藏和最近使用时间，并可选归属空间。

- 空间是可选整理层；全局搜索、收藏、最近使用均跨空间。
- 常用条目提供“打开目标”“打开所在文件夹”“复制地址”“编辑”等动作。
- 本地目标失效时保留记录并允许编辑修复；打开失败要在页面显示原因，不能只显示后台启动请求已提交。
- 目录打开自身；文件可由系统默认程序打开，或定位到所在目录。
- 工作空间根目录可一键打开；常用路径可快速收藏。
- 网页只允许 HTTP(S)。工作台不执行目标路径作为命令。
- 账号文件只保存路径和用户说明，不读取内容。

## 操作反馈与恢复

停止、重启、结束普通进程、导入 PM2 和保存快照等操作显示处理中状态并禁止重复提交。完成后刷新相关数据，显示实际结果；失败时保留上下文、解释原因并给出下一步。删除/结束等破坏性操作在确认界面显示对象和影响。

PM2 成功变更后保存快照；保存失败独立显示，不能掩盖服务操作本身是否成功。恢复区域需分别显示最近快照和 Windows 登录恢复配置。新增“验证恢复”能力前必须定义安全演练方式，不能为了测试服务而重复启动有副作用的生产进程。

## 不在本轮范围

- 公网/多用户服务、远程桌面控制和云端同步。
- 替代成熟项目发布系统。
- 任意 GitHub 项目的一键下载并执行、未经审查的自动插件市场。
- 全盘私人文件内容索引、账号密码保存或读取。
- 把所有桌面 GUI 软件都作为 PM2 后台服务运行。

## 验收场景

1. 首页能区分 PM2 未连接、服务进程停止/异常、健康检查失败和未监测。
2. 本机进程页显示所有查询到的进程；PM2 进程用 PM2 操作，普通进程确认后结束，系统进程无危险操作。
3. 对未托管程序可选择只关注或按明确配置交给 PM2；交接验证失败不关闭原进程。
4. 用户登记一个本机程序为快速打开入口后，可从收藏和统一搜索找到；它不被标记为 PM2 托管。
5. 为适合后台运行的程序配置 PM2 后，可以启停、查看日志、配置健康检查并保存恢复快照。
6. 全局搜索可找到所有已登记工作台条目；工作空间不成为打开条目的必经路径。
7. 工作台目录/文件可打开目标或所在文件夹；文件夹打开失败时网页显示错误；失效条目可以修正。
8. 引入插件后，其说明和可用能力可见；插件加载故障不会阻断总览、服务管理和搜索。
9. 项目发布、告警和插件设置仍能访问，但不压过日常服务状态和常用工作入口。

## 实现阶段建议

1. 修正进程完整清单、PM2/普通进程操作区分、工作台打开目标/文件夹和清晰失败反馈。
2. 将关注服务、健康检查和 PM2 恢复状态在首页分开呈现，并补足统一搜索与快速打开。
3. 提供软件登记目录：先支持快速打开和 PM2 服务两种实用接入，再按用户实际挑选的软件逐个评估外部项目或深度集成。
4. 有明确软件需求后再决定是否采用 Flow Launcher 插件、现有服务适配器或新增本机插件；不预先开发通用插件市场。
